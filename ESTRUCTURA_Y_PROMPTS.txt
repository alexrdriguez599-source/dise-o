================================================================================
 URBAN AI GARDEN DESIGNER — ESTRUCTURA COMPLETA, CONEXIONES Y PROMPTS BLINDADOS
================================================================================
 Documento técnico paso a paso. Plataforma SaaS de paisajismo con IA para
 paisajistas mexicanos. Render fotorrealista (WaveSpeed / Google Nano-Banana Pro),
 multiusuario con autenticación, inventario, proyectos, CRM y simulación GeoSim.

 REGLA DE ORO (PRODUCCIÓN): los prompts de cada módulo están BLINDADOS.
 La IA JAMÁS debe cambiar colores, materiales ni posiciones, ni inventar
 elementos que no estén en el diseño. "Recolor nothing, invent nothing."
================================================================================

 1) BASE DE DATOS — lib/db  (Drizzle ORM + PostgreSQL)
================================================================================
Archivo fuente de verdad del esquema: lib/db/src/schema/index.ts
Config del pool de conexiones:        lib/db/src/index.ts
  (pool: max=20, idleTimeout=30s, connectionTimeout=5s)

TABLAS PRINCIPALES:
  • users      → cuentas (username, password hash bcrypt, role, credits, status)
  • usageLogs  → bitácora de consumo de créditos (userId, action, creditsUsed)
  • projects   → proyectos de diseño guardados (datos del cliente + lienzo)
  • inventory  → inventario por usuario, sincronizado del catálogo admin

CONEXIÓN: tanto el backend (api-server) como las libs importan `@workspace/db`.
Los créditos se descuentan de forma ATÓMICA con SQL `credits = credits - N`
para evitar condiciones de carrera con peticiones concurrentes.

 2) BACKEND — artifacts/api-server  (Express 5)
================================================================================
Punto de entrada:     src/index.ts      → arranca el servidor (lee PORT)
Configuración Express: src/app.ts        → middlewares, CORS, JSON, montaje rutas
Logger:               src/lib/logger.ts → logging (req.log en handlers, logger global)
Seed admin:          src/lib/seed-admin.ts → crea el admin inicial al arrancar
                       (requiere ADMIN_SEED_USERNAME / ADMIN_SEED_PASSWORD)

MIDDLEWARE DE AUTENTICACIÓN: src/middlewares/auth.ts
  • Extrae el JWT (cookie o cabecera Bearer)
  • requireAuth  → exige sesión válida
  • requireAdmin → exige rol admin
  CONEXIÓN: casi todas las rutas pasan por requireAuth; las /admin por requireAdmin.

--------------------------------------------------------------------------------
 RUTAS (src/routes/*) — cada módulo y sus endpoints
--------------------------------------------------------------------------------
  index.ts      → registra y monta todas las rutas bajo /api

  auth.ts       → /api/auth/login, /logout, /me
                  Login usuario+contraseña → emite JWT (cookie, sesión 7 días)

  ai.ts         → /api/ai/chat, /identify-plant, /suggest-design,
                  /design-plan, /analyze-garden
                  Herramientas IA de alto nivel + descuento de créditos.
                  (chat/identify/suggest/analyze son placeholders por ahora;
                   design-plan SÍ genera lista de materiales/BOM real.)

  wavespeed.ts  → /api/ai/wavespeed/inpaint, /apply-material, /design-auto,
                  /render-final, /magazine-render, /clean-terrain,
                  /status/:jobId
                  ★ MÓDULO CENTRAL DE RENDER IA. Orquesta WaveSpeed.
                  Aquí viven los prompts blindados (sección 5).

  inventory.ts  → /api/inventory  (GET/POST/PUT/DELETE)
                  Inventario por usuario. Cache en memoria (TTL 10 min).

  projects.ts   → /api/projects  (GET/POST/PATCH/DELETE)
                  Guardar/cargar proyectos. Whitelisting de campos en updates
                  (no se puede sobrescribir userId, createdAt, etc.).

  admin.ts      → /api/admin/users, /users/:id/credits, /usage-logs,
                  /sync-catalog, /payments
                  CRUD de usuarios, gestión de créditos (atómica), pagos,
                  sincronización de catálogo (paralelizada con Promise.allSettled).

  geosim.ts     → /api/geosim/*    motor de simulación de crecimiento de plantas
  learning.ts   → /api/learning/*  contenido educativo
  download.ts   → /api/download/*  descargas/exportaciones
  health.ts     → /api/healthz     verificación de salud

PATRÓN ASÍNCRONO DE RENDER (importante):
  Los renders de IA pueden tardar. El backend:
   1. Llama a WaveSpeed (startJob).
   2. Si termina rápido → devuelve { imageBase64 } directo.
   3. Si tarda → devuelve { jobId, status:"pending" }.
   4. El frontend hace polling a /api/ai/wavespeed/status/:jobId cada 3s
      hasta status "completed" (con imageBase64) o "failed".
  Esto mantiene cada petición HTTP por debajo del límite de 120s del proxy.

 5) PROMPTS BLINDADOS POR MÓDULO  ★★★ NO MODIFICAR SIN PERMISO EXPLÍCITO ★★★
================================================================================
 PRINCIPIOS VALIDADOS (aplican a todos los prompts de render):
   • PROMPT CORTO Y ESTRICTO. Prompts largos hacen que el modelo "promedie"
     instrucciones, desobedezca e invente. Corto = máxima fidelidad al diseño.
   • USAR VERBOS ACTIVOS para renderizar ("Transform/Convert this design into a
     photo"). Frases pasivas ("keep unchanged, add realism only") hacen que el
     modelo devuelva una copia plana sin realismo.
   • FIJAR COLOR Y MATERIAL DE CADA OBJETO explícitamente. "Keep in place" no
     basta: el modelo recolorea (una tumbona NEGRA salió BLANCA = error crítico).
   • LAS SOMBRAS necesitan dirección de luz explícita; sin ella el render sale
     plano y sin profundidad.
   • PROHIBIDO INVENTAR: "Recolor nothing, move nothing, invent nothing."

 5.A) RENDER REVISTA / MAGAZINE-RENDER  (Google Nano-Banana Pro)
      Ubicación: artifacts/garden-designer/src/pages/presentacion.tsx
                 función buildNanaBananaPrompt()
      Modelo:    google/nano-banana-pro/edit
      NOTA del modelo: NO acepta strength, guidance_scale, negative_prompt,
                       seed ni num_steps. La única palanca de calidad es el texto.
      ★ ESTOS DOS PROMPTS ESTÁN APROBADOS POR EL CLIENTE Y CONGELADOS ★
--------------------------------------------------------------------------------
  MODO "CREATIVO" (cinematográfico, luz cálida de tarde):
  --------------------------------------------------------
  "Transform this design into a cinematic 8K HDR photograph. Warm afternoon
   sunlight, dramatic realistic shadows, depth of field. Keep every object's
   exact color, material and position — furniture keeps its original color.
   Recolor nothing, move nothing, invent nothing."

  MODO "CONSERVADOR" (hiperrealista de día, luz clara, sin amarillo):
  ------------------------------------------------------------------
  "Convert this design into a hyperrealistic 8K DSLR photo. Bright clear
   daylight, soft long shadows, realistic grass and leaf texture, sharp natural
   detail. Keep every object's exact color, material and position. Recolor
   nothing, invent nothing."

  Historial (para NO repetir errores):
   - Conservador con "golden-hour/warm" salía demasiado amarillo e idéntico al
     Creativo → se cambió a "bright clear daylight" (sin cálido/dorado).
   - "soft long shadows" son las sombras aprobadas por el cliente — conservar.
   - "hyperrealistic 8K DSLR photo" + "realistic grass and leaf texture, sharp
     natural detail" fue lo que quitó el aspecto de render 3D/CGI.
