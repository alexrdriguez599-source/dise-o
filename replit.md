# Urban AI Garden Designer

A professional SaaS platform for Mexican landscapers. Clients upload a photo of their site, apply AI-powered materials (grass, stones, volcanic rock, marble), generate full design renders, and export PDF presentations. Admins manage users, credits, inventory, and sync catalog items.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080, proxied at `/api`)
- `pnpm --filter @workspace/garden-designer run dev` — run the frontend (port 23086, proxied at `/`)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL`, `SESSION_SECRET`, `WAVESPEED_API_KEY`, `ADMIN_SEED_USERNAME`, `ADMIN_SEED_PASSWORD`

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React + Vite, Tailwind CSS v4, wouter, @tanstack/react-query, Three.js, Leaflet, Recharts, framer-motion
- API: Express 5, JWT auth (cookie + Bearer), bcryptjs, multer
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- AI: WaveSpeed API (flux-fill-dev, flux-kontext-dev, google/nano-banana-pro)
- Build: esbuild (CJS bundle)

## Architecture decisions

- **Contract-first API**: routes defined in `lib/api-spec/openapi.yaml`; custom garden hooks live in `garden-hooks.ts` (not generated by Orval — these predate the Orval setup)
- **Field whitelisting on updates**: PUT/PATCH for projects and inventory only allow a specific set of fields — prevents clients from overwriting `userId`, `createdAt`, etc.
- **Atomic credit updates**: admin credits endpoint uses `credits = credits + N` SQL to prevent race conditions under concurrent requests
- **Parallelized sync-catalog**: `Promise.allSettled` over all users instead of sequential per-user loop
- **No inventory list cache**: the inventory `GET /` always reads from the DB (source of truth). A previous per-process in-memory cache was removed because on autoscale (multi-instance) it served stale reads — a POST invalidated only the handling instance's cache, so a later GET on another instance returned a stale list and freshly-added items appeared to vanish on reload. The list query projects all columns **except** `image_data` (adds a computed `hasImage`); images are served separately via `/:id/image`. If a cache is ever reintroduced for scale, it must be shared (Redis/Upstash), not per-process.
- **WaveSpeed retry tokens**: in-memory Map — per-process, so not safe across multiple instances (autoscale)
- **DB pool**: max=20, idleTimeoutMillis=30s, connectionTimeoutMillis=5s

## Product

- **Login / Auth** — username+password, JWT cookie, 7-day sessions
- **AI Design Studio** — upload garden photo → apply grass/stone/materials via inpainting, generate full designs
- **Magazine Render** — professional photorealistic render via Google nano-banana-pro
- **GeoSim** — multi-year plant growth & water simulation engine
- **Inventario** — per-user inventory synced from admin catalog
- **Proyectos** — save/load design projects with client info

- **Admin Panel** — user CRUD, credits management, payment logging, catalog sync, usage analytics

## User preferences

### Reglas de trabajo (obligatorias)

**Principios**
1. SIEMPRE leer y entender el código existente ANTES de editar. Nunca editar a ciegas.
2. Cambios quirúrgicos: tocar solo lo mínimo necesario. No refactorizar de paso.
3. Antes de cambiar archivos, presentar SIEMPRE: (a) diagnóstico, (b) lista de archivos a tocar y los que NO se tocarán, (c) plan paso a paso. Esperar aprobación.
4. NUNCA tocar el motor de render de texturas/perspectiva del canvas salvo que sea explícitamente el objetivo de la tarea.
5. NUNCA tocar la lógica de cotización, precios ni el módulo de plantas cuando se trabaja en otro módulo.

**Disciplina de debugging**
- Cuando una función falla pero otra casi idéntica funciona, comparar AMBOS caminos completos (frontend → endpoint API → base de datos) y hallar dónde divergen. No adivinar.
- Toda corrección de persistencia se verifica con la prueba de recarga: guardar un dato, recargar la página, confirmar que sigue ahí.

**Zonas críticas que ya funcionan (NO romper)**
- Módulo de plantas: persistencia y catálogo (es la referencia).
- Render de texturas sobre zonas dibujadas.
- Colocación/perspectiva de objetos (albercas, muebles).
- Cálculo de cotización y precios.

**Reglas del producto**
- Materiales y plantas son catálogos separados pero comparten el patrón de persistencia.
- Lo que sube el admin (sin userId / categoría global) debe aparecer precargado para todos los clientes.

**Después de cada cambio**
- Confirmar explícitamente qué se verificó que sigue funcionando.
- Si algo se rompió, revertir en lugar de seguir parchando.

## Gotchas

- `pnpm run dev` at workspace root is intentionally absent — use workflow restarts instead
- `ADMIN_SEED_USERNAME` / `ADMIN_SEED_PASSWORD` must be set before first start or admin won't be seeded
- The inventory in-memory cache is per-process. On multi-instance deployments a write on one pod won't invalidate the other pod's cache
- WaveSpeed API key must be set or all AI render endpoints return 500
